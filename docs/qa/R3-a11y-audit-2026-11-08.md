# R3c accessibility audit (2026-11-08)

> Scope: hub (signed out + signed in), Events list, event page (Map · List · Sign-Up, plain + every look:
> Halloween pins, Haq al Laila, Holiday Lights, event day, archived), My Home (Home · Household · Account incl.
> R3a Settings + page help dialog), Organizer Tools (Events · Banner · Community + new-event editor), account.
> Plan: `docs/plans/R3-app-shell.md` F (P1–P7 preliminary findings), Step 8 R3c, Decision 4 (axe test-only).
>
> Method: (1) **axe-core 4.14.0** (`@axe-core/playwright`, tags wcag2a/aa + wcag21a/aa + best-practice) on 25
> screen states × EN + AR, both e2e lanes (Chromium iPhone 13 + WebKit iPhone 13), stubbed backend; (2) code read
> for keyboard / screen-reader behaviour (roles, names, focus order + visibility, focus after redraw, `lang`);
> (3) contrast computed for every token pair incl. the event looks; (4) a 195 CSS px viewport (= 200 % page zoom on
> a 390 px iPhone) screenshot pass, EN + AR. **Not done:** VoiceOver on a real iPhone (R8 real-device pass).

## Findings

| # | Sev | Where | Finding (WCAG 2.1) | Disposition |
|---|---|---|---|---|
| A1 | **Serious** (axe `color-contrast`) | `--jc-faint` text (`.help`, `.tag`) on panels: My Home (tag), Account + Settings (6 nodes), Organizer Banner + Community | `#878072` = **4.33:1** on `--jc-surface`, **3.84:1** on `--jc-surface-2` (Settings' fixed My Home row) — fails 1.4.3 for 12–12.5 px text. The 2026-11-02 brand note said faint belongs on `--jc-bg` only; the screens use it on panels anyway | **Fixed**: `--jc-faint` → `#9A9384` (6.12 / 5.56 / 4.93:1 on bg / surface / surface-2; ≥ 4.85:1 on every look's surfaces). `docs/brand.md` updated |
| A2 | **Serious** (axe `link-in-text-block`) | every Leaflet map (event map, pins) | Leaflet's attribution link is told apart from its text by colour only (2.55:1) — 1.4.1 | **Fixed**: underlined (`app.css`) |
| P1 | Med | the 3 sub-tab rows (event, My Home, Organizer Tools) | `role="tab"` without `tabpanel`, `aria-controls`, roving tabindex or arrow keys; no accessible name on the tablist; focus lost on redraw in events + My Home (4.1.2, 2.4.3) | **Fixed**: shared `nav.js` `jcTabsHtml` / `jcTabPanel` / `jcTabsWire` — named tablist, `aria-controls` → `role="tabpanel"` (`aria-labelledby`), roving tabindex, ←/→ (mirrored in Arabic) + Home/End with wrap, focus back on the selected tab after the redraw; `?tab=` URLs and replaceState unchanged |
| P3 | Med | `app.css` | `:focus-visible` ring only on `input, button, a`; textarea (banner, editor, feedback), select, `<summary>` (Settings install help) and Leaflet keyboard markers fall back to the browser default on a dark surface (2.4.7) | **Fixed**: same 2 px accent ring on textarea, select, summary, `[tabindex]` (not `-1`) |
| P5 | Med | events / My Home / Organizer Tools `show()` | whole-view `innerHTML` redraw drops focus to `<body>` after Save / Publish / confirm unless the view focuses something (2.4.3) | **Fixed (generic)**: `jcFocusKeep()` wraps each page's `show()`: if the new view took no focus, focus returns to the same control (by id; never a text field, so no iOS keyboard), else the selected tab, else the view heading (tabindex −1, no ring, no scroll). Background refreshes (event-day 2-min, map) don't go through `show()`. `account/` already focuses its first input |
| A3 | Med (2.4.6 / 1.3.1, axe moderate `page-has-heading-one`) | My Home (all tabs) | no level-one heading: a screen-reader user lands on a tab row with no screen name | **Fixed**: visually hidden `<h1>` "My Home" |
| P2 | Low | `nav.js` bottom bar | `<nav aria-label>` = "Commons", same as its first button (2.4.6) | **Fixed**: "Main" / AR "القائمة الرئيسية" (DRAFT AR) |
| P6 | Low | language button (every page) | label is in the *other* language with no `lang`, so it's read with the wrong voice (3.1.2) | **Fixed**: `jcSetLang` sets `lang` on `#langBtn` |
| A4 | Low (axe moderate `page-has-heading-one`) | account page when already signed in | no `<h1>` on the signed-in account view | **Follow-up** (tiny; out of the four main screens) |
