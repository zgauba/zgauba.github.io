## Findings (Phases 6–7)

Evidence is code (live definitions) unless marked **live data**. The e2e suite could not be re-run this session:
port 4173 was held by the parallel R0 run. The last full run was green (273/273, 2026-11-06).

### Data-integrity

**D1. A hidden sign-up stays hidden for the next family.** (Mode 1, no mitigation, no test)
`jc_home_vacated` withdraws the leaving family's entries and clears payload, notes and event pin, **but not `hidden`**.
`jc_event_signup`'s re-join branch resets live state, supply, report lock, event pin and spot, **but not `hidden`**.
*Repro:* organizer hides Villa X's sign-up → that family leaves → a new family claims Villa X and signs up →
`hidden = true`. They're missing from the map, the list and `homes_in`, and their screen doesn't say so (see U1).
Same household withdrawing + re-joining also stays hidden; that part is arguably intended.

**D2. Events never end on their own, so the event's record depends on someone remembering to close it.** (Mode 2)
Nothing acts on `ends_at`: there's no job, and the client's "Past" list is `status = archived` only.
**Live data:** `e2e/halloween-test` ended 2026-11-06 06:50 UTC and is still `live` with `signups_open = true`.
Consequences: (a) after the night it sits under upcoming events with **Sign Up** still offered; (b) `jc_event_stats`
is written only by `jc_event_close`, so a forgotten close means no snapshot, the same silent-zero-capture failure
as the Halloween 2026 retro; (c) the 5-day read window for event admins never starts; (d) an organizer's banner
about the event stays up (see U3).

### Functional

**F1. The Halloween and Haq al Laila templates turn on the switch only, not supply or crowd reports.**
`TEMPLATES` sets `features: { giant_switch: true }`; the supply gauge and "They're Out of Treats" stay off
unless the organizer ticks two boxes in the Features fieldset. **Live data:** all three e2e treat events have
all three ticked, but by hand. A template built before event day shipped (2c) was never updated by 5b.
`[ASSUMED: defaults should be all three on for treat nights. Zee to confirm]`

**F2. A homes event with no start date never gets event-day controls, and nothing says so.**
`eventDay()` returns false without `starts_at` (5b: "undated: never"). The editor's publish check
(`missingForPublish`) asks a homes event for a title only. An organizer who skips the date publishes a treat
night with no switch, no supply and no reports.

### UX (high impact)

**U1. Households aren't told they're invisible.** `jc_event_get` shows admin-hidden entries and
directory-suppressed homes **only to their own household** (by design, SQL test E21). My Sign-Up shows nothing
different (`events.js` never reads `hidden`; no string mentions it). On a treat night that household hands out
nothing to no one and never learns why. It's the same pattern as the known pin-move gap (synthesis S2):
**an organizer acts, the household isn't told.**

**U2. No organizer withdraw for a no-show** (known: 3b #9, PR 4). On capacity events a hidden sign-up also
holds its place, so hiding doesn't free one either.

### Cosmetic / low

**U3. Banners outlive their reason.** `jc_event_close` clears only a banner set by that event's admins
(`broadcast_event`). An organizer's banner about the event stays. Revoking an event admin
(`jc_event_admin_revoke`) leaves their banner up until the event closes. An organizer can clear either.

**L1. A vacated home's withdrawn row keeps its spot.** `jc_entry_withdraw` nulls `spot`; `jc_home_vacated`
doesn't. Spot uniqueness is among `in` rows, so it blocks nobody, but the CSV (which includes withdrawn rows)
shows it.

### Checked, no issue

Crowd reports are deduped per **household** (one per reporting home, not per member), capped at 10 open per
reporting home per event, never on your own home, and the reporter is never returned. The household's "Done"
clears reports. Withdraw frees the spot and clears reports. Re-join resets event-day state. Close row-locks
against sign-ups. Event admins are scoped by event and community. Venue events never send homes to residents.

## Questions for Zee: answered 2026-11-06, all yes ("fix all the bugs"); folded into ROADMAP R2a

2. **D2:** at the end time, should the event (a) stop sign-ups and move to Past, auto-closing N hours later, or

4. **D1:** should moderation reset when a new family moves in? (Recommendation: yes. Clear `hidden` in
   `jc_home_vacated`; keep it across the same household's withdraw + re-join.)
