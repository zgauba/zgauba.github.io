## What shipped

**Database (one migration)**
- `jc_events_look_check`: dropped and re-added in one `ALTER TABLE` with `holiday_lights` added (seven looks).
- `jc_admin_event_save(p_event uuid, p_fields jsonb)`: **body only**. The argument list, `SECURITY DEFINER`,
  `search_path` and grants are unchanged (`create or replace`). It starts from the live `pg_get_functiondef`, which
  is identical to `20261106120000_r2a_events_audit.sql`. Changes are marked `R2b-2`:
  - **safety**: only the keys `phone`, `meeting_en` and `meeting_ar` are allowed; anything else is `BAD_FIELDS`.
    - Phone: whitespace runs collapse to one space and the result is trimmed. It must match
      `^\+?[0-9]( ?[0-9])*$`, with 3–15 digits and ≤ 24 characters, else the new code `BAD_PHONE`.
    - Meeting points: `jc_clean_line`, ≤ 200 characters.
    - Blanks are dropped, so `{}` clears the block. The stored object is rebuilt from the three keys, never copied
      from the input.
  - **text**: `title_en` / `title_ar` get whitespace runs → one space, then `jc_clean_text`.
    - `description_en` / `description_ar` get `jc_clean_text`, so their newlines are kept.
    - A title that cleans to nothing is `BAD_FIELDS` (it was accepted before).
    - Blank optional text is stored as `null`.
    - Existing rows are untouched.
- No new function, table, column, grant or RLS change. `jc_event_get` / `jc_admin_events_list` are untouched and
  already return `safety`.

**Client**
- Editor (`admin/admin.js`): a **Safety** section with:
  - a checkbox (`features.safety`);
  - the security number (`type="tel"`, LTR; Arabic-Indic numerals become 0–9 before sending);
  - meeting point EN / AR;
  - help text saying "the community's security line, never a resident's own number" and "never write a child's name".

  Client checks mirror the server: `BAD_PHONE`, and `SAFETY_EMPTY` (ticked with nothing filled). Each says so in
  words and sends nothing. Only changed fields are sent, as before. Unticking keeps the text.
- Event page (`events/events.js`): a compact two-line box under the description, shown only when the switch is on,
  something is filled in, and the event isn't archived.
  - "🛡️ Security: ⟨number⟩" is a `tel:` link built from numerals and `+` only, and only when the number passes
    `jcSafetyPhoneOk`; otherwise it shows as text.
  - "📍 Lost child? Meet at: ⟨place⟩" uses the current language, falling back to the other.
  - Everything goes through `esc()`.
- Holiday lights:
  - Look: tokens.css, evergreen night with string-light gold `#ffcf66`; it never sets the four signals.
  - Mark: ✨.
  - Template: homes, switch only, safety not pre-ticked. Questions: "Best seen from…" (ring, split for both),
    "What kind of lights?" (icon 💡🌈🎶), "Lights on until…".
- `assets/api.js`: shared `jcSafetyPhoneOk`. `assets/app.css`: `input[type=tel]` shares the text-input style (16 px,
  so iOS doesn't zoom).
- Strings EN + AR (Arabic is a DRAFT pending review, like the rest). "Holiday Lights" in Arabic is "أضواء الزينة"
  (decoration lights), chosen to be faith-neutral.

## Self-review notes

- **Zero-PII:** the block holds a community service number and a place. The server refuses any other key (so no
  `child_name` can be smuggled in) and the help text says never to write a child's name. Nothing links a child to a
  home.
- **`jc_event_get` returns `safety` whatever the switch says** (decision 4): community information, unchanged read
  path. The switch is a display switch, not an access control.
- **Mixed-cache window:** `admin.js` / `events.js` call `jcSafetyPhoneOk` from `api.js`. During the ~10 min CDN
  window a stale `api.js` could sit next to a new page script. Both calls are guarded with `typeof … === "function"`.
  If the helper is missing, the number shows as text (no link) and the server still checks it, so the event page
  can't throw on event night.
- **Deferred:** lights-specific switch wording ("Lights on / Lights off"), per decision 6.
