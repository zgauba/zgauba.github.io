## Deviations from the plan (recorded)

1. **Icon cut:** the plan says "the reduced 6-dot cut used for the favicon". `docs/brand.md` says the reduced
   cut is for anything under 24 px and the **full cut (8 dots + center) for 24 px and up**. Home-screen icons are
   about 60 pt, so the icons use the **full cut, on-dark colorway** (center `#6FCF8F`, dots `#3E9B76`) on an opaque
   `#141210` square. That is the same mark the top bar of every page shows. Mark width: about 70 % for `any` and
   apple-touch, about 60 % for maskable (well inside the 80 % safe circle).
2. **`id` resolved:** MDN (checked 2026-11-08): a relative `id` resolves against the **origin** of `start_url`. `"/"`
   gives `https://commons.ae/`, the same value Chrome would infer today from `start_url`. It is frozen from now on;
   the spec asserts it.
3. **`mobile-web-app-capable`** was added beside the Apple tag: Chrome logs a deprecation warning when the Apple tag
   stands alone.

## How the icons were made (no build step added)

Rendered once with Playwright Chromium (from `tests/e2e/node_modules`): an inline SVG of the full-cut mark, viewBox
padded by 8 units (`any` / apple) or 18 units (maskable) around the 96-unit mark box, filled `#141210`, screenshot at
`deviceScaleFactor: 1` at each pixel size. Output: 8-bit RGB, no alpha (`sips` + spec check). To redo it, repeat the
same SVG at the same sizes. Don't change the icons after residents install: an installed icon can't be updated.

## Static by design (premortem 2b(b)/(c), 7)

The installed name and icon are copied onto each phone at install and can't be changed by us. The name was chosen
before any resident can install (Decision 3, launch rule). Browsers re-fetch the manifest themselves, and nothing in
the running page depends on it, so it doesn't need to be in `update.js`'s fingerprint. A revert of this PR leaves
already-installed icons opening `commons.ae/` as a plain window, which still works.

## Independent review: `code-reviewer` (2026-11-08)

Verdict: **APPROVE**. Nothing High or Med. The reviewer ran the spec (16/16) and confirmed: the `id` and relative URLs
resolve as intended on both hosts; the icons are 8-bit RGB with no alpha at their declared sizes; the maskable mark
reaches about 174 px from center against a 205 px safe radius; the head tags are identical across the five pages with
correct relative paths; 404 is correctly left out; `black` suits the dark default; the `getAppManifest` check is sound;
reading the served HTML through `request.get` avoids the signed-out redirect; `networkidle` is safe with the stubbed
backend. Open, as the reviewer noted: whether current Chrome on Android needs a service worker for the install
**prompt**. A DevTools Application → Manifest / Lighthouse pass on commons.ae after deploy settles it. Under Decision 5
the menu's "Install app" / "Add to Home screen" is enough either way.
