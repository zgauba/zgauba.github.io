## Database review (database-reviewer)

**Verdict: safe to apply. No Critical or High findings.** The reviewer checked these and found them sound:
- The rollup can't shrink a kept count: ended rows are immutable and hours are purged whole.
- The precedence of the grid `home` CASE is correct.
- The active cap is race-safe under the home row lock.
- There is no deadlock cycle.
- Unpublish and walk-on are serialized on the facility lock.
- The DDL is safe on empty tables.
- `cron.schedule` is idempotent.

## Security review (security-reviewer)

**Verdict: safe to apply. No Critical, High or Medium findings.** The reviewer confirmed these:
- The resident grid never returns another home's id, booking id, privacy flag or a name.
- `jc_booking_privacy_set` has no IDOR (it is keyed on `home_id = jc_me().home`, and every miss returns the same `NOT_FOUND`).
- Every resident path checks the kill switch first.
- Courts admin needs a `bookings` or `community` grant.
- The grants are right: internal helpers are revoked, and `CREATE OR REPLACE` keeps the closed ACL on `jc_facility_grid`.
- Nothing with a user or home id survives 90 days outside `jc_admin_log` (admin ids only).
- Residents only see homes inside the booking window, not 90 days of history.

## Out-of-scope test fix (called out)

`s16_safety_lights` L01a read `v -> 0` from `jc_admin_events_list`, which orders by `created_at desc`. Every row
created in one transaction ties, so position 0 is nondeterministic. It passed on the baseline but failed once R4a's
slices ran before it. The check now selects the event by id. The test's intent is unchanged.
