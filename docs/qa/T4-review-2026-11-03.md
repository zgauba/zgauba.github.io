# T4 review — instrumentation + cleanup (database + security), 2026-11-03

> Pre-apply gate for the T4a/T4b/T4c migrations, the `jc-photo-purge` Edge Function and
> the canary workflow. Both reviewers read the code and tests; the dry run (371 checks)
> is the execution check. Saved per KG13.

## Verdict

One high (database) and two mediums (security) — all fixed before apply. The dry run then
surfaced two more defects the reviews missed; both fixed (below).

## Database review

| Sev | Finding | Disposition |
|---|---|---|
| **High** | `jc_admin_report` raised when `jc-hourly-snapshot` was missing — reading an unassigned record — i.e. it failed in exactly the case it exists to report | **Fixed** — unconditional `SELECT INTO` (NULLs on no row). N10 unschedules the job and asserts the report answers with `job_present: false` and `jc_health.ok: false`. |
| Med | `(modules->'x'->>'enabled')::boolean` cast: one malformed modules row aborts the snapshot for every community | **Fixed** — compared as text (`is not distinct from 'true'`). |
| Med | Events / bookings / pets metrics had no assertions | **Fixed** — N02 fixtures for every module. |
| Med | The outside probe couldn't see a broken purge (pg_cron logs "succeeded" as soon as the HTTP call is queued) | **Fixed** — `jc_health.maintenance_ok` (stale > 36 h or last run errored); C06e–g. |
| Low | Orphan purge had no floor on its window; cascade from `jc_rate` untested | **Fixed** — `BAD_DAYS` under 7; o5 fixture. |

## Security review

| Sev | Finding | Disposition |
|---|---|---|
| **Med** | pg_net's request queue (`net.http_request_queue`, `net._http_response`) is readable by anon **at the grant level**; a Vault secret sent as a header would sit there on every run | **Redesigned** — single-use nonce minted per cron run (`jc_cron_nonce_new`), spent by the function (`jc_cron_nonce_use`: unused, < 10 min). Revoking anon's grants was attempted and is a silent no-op (`supabase_admin` owns them). Safe today only because `net` isn't API-exposed (406 PGRST106, verified). |
| **Med** | The function called the database on every junk request (unauthenticated amplification) | **Fixed** — method + header shape checked before any DB call. Verified live: no header / junk / unknown nonce / GET → 403. |
| Low | The "schemas not exposed" defence had no guard | **Fixed** — canary probes 7 internal schemas every 6 h (must stay 406); G16 no USAGE on `cron`; G17 no public function references `net.`/`vault.`; G18 only the three monitoring functions read `cron.`. |

## Found by the dry run (missed by both reviews)

| Finding | Disposition |
|---|---|
| Supabase's default privileges give **service_role EXECUTE on every public function** (verified live: all 106). C05f caught `jc_cron_nonce_new` callable with the key the Edge Function holds | **Fixed** — explicit revoke. Not exploitable (that key is already full admin), but it broke the "only cron mints" invariant. Other internal functions stay service_role-callable by platform default — accepted. |
| `jc_maintenance_status` picked "latest run" by `at` alone; rows in one transaction tie, so a recovered job could still read as erroring (C06g) | **Fixed** — `order by at desc, id desc`. |

## Net change

Tests 309 → 371 (00_grants +3, s6 29, s7 30).
