# R4b-1a — Admins screen + invite links: reviews and dispositions (2026-11-08)

PR: `feat/r4b1-admins-ui`. Plan: `docs/plans/R4b-1-admins-courts.md` (approved 2026-11-08). Tier: auth-adjacent screen logic,
client only (no migration) → **security-reviewer + code-reviewer**. Both reviewed commit `6e16e34`; fixes in the next commit.

## Security review: no High findings

| # | Sev | Finding | Disposition |
|---|---|---|---|
| 1 | M | The `&role=` hint in the link is attacker-editable. A community token labelled `role=bookings` reads as "Courts" but grants root, so the invitee consents to the wrong thing | **Fixed.** The link carries no role (`#admininvite=<token>` only; a link with `&role=` is rejected as malformed). The question never names a level: it says the sender chose it, that it's named right after accepting, and how to get removed. The server's answer names the granted scope. Test: "names no level", "malformed invite fragment (incl. a role hint)" |
| 2 | M | The invite is lost silently when sign-up crosses a tab (email confirmation, an in-app browser → Safari): sessionStorage is per tab | **Mitigated, accepted.** The link maker's help text now says the invitee may need to open the link again after signing up. The link stays valid until used, so reopening works. Carrying the fragment through `next` is a larger change (`jcSafeNext`), left for later if it bites |
| 3 | L | The stored token outlives the decision (whole tab life; shared device) | **Fixed.** Stored with a timestamp and ignored and cleared after 1 h; cleared on `SIGNED_OUT` (`api.js` `onAuthStateChange`). Test: "older than an hour … signing out forgets it too" |
| 4 | L | The one-time link is visible on screen (screenshots / screen share) | **Accepted.** Same pattern as the live per-event admin links (T5.2 PR B). Copy / Share are the normal path; the community link is 24 h, at most 3 open, and the list shows who accepted |
| 5 | L | Admin caches (`hh`, `hlog`, `health`, `fb`) survive self-removal / `fail()` | **Fixed.** Cleared on self-removal; `hh` / `hlog` / `health` cleared in `fail()` |
| 6 | L | Link base is `location.origin + location.pathname` | **Accepted.** Same as the per-event links; both origins (commons.ae, zgauba.github.io/commons) serve the same page |
| 7 | Note | Browser history may hold the original fragment URL before `replaceState` | **Accepted.** The 24 h / single-use limits are the real mitigation |
| 8 | Note | Widened `canEnter` for courts-only admins is acceptable; Add code / Lock still shown | **Noted.** Hiding the code UI comes with code retirement (R4a-3 S10) |
| 9 | Note | Self-removal flow correct | — |

Confirmed sound: the token never reaches a server, `next=../admin/` carries no token, `no-referrer`, every new string through `esc()`, CSP `script-src 'self'`, R4a-2 S9 + R4a-3 D3 done.

## Code review: approve with changes

| # | Sev | Finding | Disposition |
|---|---|---|---|
| M1 | M | The one-time link is wiped by unrelated actions (another level's Remove / Cancel / Make, NOT_FOUND reload) | **Fixed.** `adLinks` holds one shown link per level and is cleared only on leaving the screen (`show()`). Redraws use `VIEWS.admins()`; the NOT_FOUND / community re-read passes the links through. Test: "a shown link survives another level's Make and Remove" (mutant `show()` → 6 tests fail) |
| M2 | M | `adBusy` stays stuck after a throw in a success handler | **Fixed.** One `write()` wrapper: `.then(done).catch(...)` always resets `adBusy`; a malformed `link_create` answer (no token) is an error, not a link |
| L1 | L | A non-NOT_ADMIN list failure leaves "Working…" for good | **Fixed.** Error shown with Try Again. Test "lists that can't be read" |
| L2 | L | No Thanks during an in-flight accept could throw | **Fixed.** Disabled while the accept is on its way; the handler keeps its own copy of the invite. Test "No Thanks is off" |
| L3 | L | A pets-only accept ends on a bare "Done" | **Fixed.** Says it worked + a Back link to Commons. Test |
| L4 | L | If `jc_me_get` fails after a self-removal, the Admins screen stays briefly | **Accepted.** The next action gets NOT_ADMIN, then `fail()` recovers |
| Note | — | Removing a community admin cancels their links at every level, but only `community` was refreshed | **Fixed.** That case re-reads every level (links kept). Test "removing another community admin … re-reads every level" |

Test gaps the review listed, all added: survival across levels, double tap = one call, list failure, NOT_ADMIN on Admins → re-check, other-community-admin removal, pets accept, No Thanks mid-accept.
