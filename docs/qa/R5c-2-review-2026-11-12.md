## What it does

- `jc_pet_photo_remove(p_pet)` — `jc_pet_manage` decides who (the household for an owned pet, a Pets admin for a
  stray; same community, active pet; module on). Clears `photo_path`; retires the current ledger row; **also cancels
  any in-flight upload** (pending columns cleared, pending row retired) so a takedown wins. No current photo →
  `NO_PHOTO`. Returns the card. Authenticated only.
- After it commits no new view can read the file (SELECT policy = current path only); signed URLs already issued live
  ≤ 1 h (`PHOTO_TTL`); the file is deleted by `jc-photo-purge` at the next 03:35 UTC run.
- Pets → Edit: **Remove Photo** (confirm: "Remove {n}'s photo? Neighbors will stop seeing it.") when a saved photo is
  shown; **Don't Use This Photo** drops a picked, unsaved one. Disclosure now says "a replaced or removed photo is
  deleted within a day".
