# R5b-2b-1 — Pets layout — review 2026-11-12

From Zee (2026-11-12): "I think the pet list can be in two columns rather than 1… also, the pet details page itself
just looks messy…" → "yes fix the pets layout first".

Tier: screen logic (client only, no DB change). Reviewer: `code-reviewer`.

## What changed

- **List**: two-column photo cards (whole card is the button; photo or paw tile on top, name, species · kind, home /
  territory, badges). Missing pets: full-width cards on top, photo beside the text, red edge, last-seen line.
- **Badges**: colour only for real states: Missing = filled red, Needs help = amber; others neutral.
- **Pet page**: compact header (photo tile beside the name, species · kind, badges; no second "Missing" badge, since the alarm says it).
  The missing alarm carries the owner's "is back home". Then **About · Sightings** tabs (shared `jcTabsHtml`,
  `?show=`); no tab row when only About applies. A missing pet opens on Sightings. Reporting missing jumps to
  Sightings, where the share is. Found jumps to About.
- **Tests / tooling**: Pets stub moved to `specs/backends.js` (`petsBackend`); `/shot` can show `pets/` screens.
